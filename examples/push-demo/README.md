# push-demo

Web Push + Notifications + a2hs (Add to Home Screen) demo for http-nu + xs.
End-to-end: subscribe in browser, persist to xs, fan-out via `nu_plugin_push`,
deliver a real notification to a real phone. Designed so you can test on your
own iPhone or Android in under a minute.

## Quickstart

```bash
# 1. Install tools (Rust, nu, fnox, cloudflared, qrencode, resvg).
mise install

# 2. Build http-nu + the push plugin.
mise run build
mise run push:plugin:build

# 3. Generate VAPID keys + admin token, store in fnox. One-time per env.
PUSH_VAPID_SUBJECT=mailto:you@example.com mise run push:vapid:generate

# 4. Start the demo + a Cloudflare quick tunnel + QR code.
mise run push-demo:dev
```

Step 4 prints a `https://random-name.trycloudflare.com` URL and a QR code in
your terminal. Point your phone's camera at the QR, open in Safari/Chrome,
follow the on-screen instructions, and you'll have working web push.

## Browser flow

- **Desktop (Chrome / Edge / Firefox / Safari macOS 13+):** click **Enable
  Notifications** -> grant permission -> done.

- **Android (Chrome / Firefox):** same as desktop. The browser may also
  prompt to install to home screen, optional.

- **iPhone / iPad (iOS 16.4+, Safari only):** install-to-Home-Screen is
  required by Apple before web push works.
  1. Tap the **Share** button in Safari.
  2. Choose **Add to Home Screen**.
  3. Open the app from your home screen icon (not from Safari).
  4. The page now shows an **Enable Notifications** button -- tap it.

You can verify each state with the debug panel: append `?debug=1` to the URL
and a panel pops up showing `isIOS`, `isStandalone`, `Notification.permission`,
and current subscription endpoint.

## Sending a notification

From the demo UI: click **Send Test Push to Me** after subscribing. This
POSTs to `/send-self` which fans out a hello notification to every active
subscriber.

From the command line (using your admin token from fnox):

```bash
TOKEN=$(mise run push:vapid:admin-token)
curl -X POST https://<tunnel-url>/send \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: text/plain" \
  --data '{"title":"hi","body":"sent from curl"}'
```

## How it works

```
browser POST /subscribe (PushSubscription JSON)
    -> serve.nu validates via `push subscription parse`
    -> .append push.subscription.added <json>

[user clicks Send Test Push]
    -> POST /send-self
    -> serve.nu: current_subs | push send $payload --ttl 60
    -> for each result: if expired, .append push.subscription.expired

next /send-self -> current_subs projection excludes the expired endpoint
```

The plugin is stateless; xs holds the subscription set; serve.nu is the glue.

## Troubleshooting

Open `https://<url>/?debug=1` to see the state machine state:

| state                   | meaning                                            | fix                                          |
|-------------------------|----------------------------------------------------|----------------------------------------------|
| `unsupported`           | Browser doesn't expose Service Worker / Push      | Use a modern browser                         |
| `ios-install-required`  | iOS Safari, not yet installed to home screen      | Share -> Add to Home Screen, then open from icon |
| `awaiting-permission`   | Ready to ask                                       | Tap Enable Notifications                     |
| `subscribing`           | Mid-flight                                         | Wait a sec                                   |
| `ready`                 | All good                                           | Test the Send button                         |
| `denied`                | Permission rejected                                | Settings -> Notifications -> allow           |

Common gotchas:

- **iOS install seems silent.** Apple does not fire any event when a user
  taps "Add to Home Screen." The state machine only flips after the user
  re-opens the app from the home screen icon. The on-screen copy says this.

- **`navigator.standalone` stays false on iPhone after install.** You're
  missing `<meta name="apple-mobile-web-app-capable" content="yes" />` in
  the page head. The included `index.html` has it.

- **`/sw.js` updates aren't picked up.** Cloudflare is caching it. Fix:
  set `Cache-Control: no-cache` on the origin response for `/sw.js`
  (serve.nu already does this), or add a Cloudflare Cache Rule.

- **Push works on Chrome but fails on Safari/iOS.** Often a VAPID issue.
  Apple requires `VAPID_SUBJECT` to be a real `mailto:` or `https:` URL.

## Security notes (real-world deployment)

- **Subscription endpoints are sensitive.** They contain identifiers a third
  party can use to push notifications. Treat the xs store as PII at rest.

- **Multi-device users have multiple subscriptions.** The unique key is the
  endpoint URL, not the user account. Join across user_id <-> endpoint in
  your own table if you need per-user views.

- **Same-origin check on /subscribe.** serve.nu rejects cross-origin POSTs
  via an Origin header check. For real apps, layer this with proper auth.

- **`/send` endpoint requires `Authorization: Bearer $PUSH_ADMIN_TOKEN`.**
  The demo's admin token is generated by `mise run push:vapid:generate` and
  stored in fnox. Anyone with this token can spam all subscribers.

- **VAPID rotation invalidates every existing subscription.** Don't rotate
  casually. See `crates/nu_plugin_push/README.md` for the full caveat.

- **xs event retention is unbounded by default.** `push.subscription.added`
  events accumulate forever. For production, see `docs/push-native/events.md`
  for the retention discussion.

- **xs handler isn't transactionally idempotent.** A crash mid-fanout can
  re-send. Browsers dedupe within a push service to a degree (especially
  with `--topic`), but don't rely on it for important state.

## Production deployment

Replace the dev tunnel with a named tunnel + your own domain:

```bash
# One-time
cloudflared tunnel login
cloudflared tunnel create push-demo
cloudflared tunnel route dns push-demo push.example.com
cp ~/.cloudflared/<TUNNEL-UUID>.json examples/push-demo/.cloudflared/credentials.json

# Edit examples/push-demo/cloudflared.yml -> set your hostname

# Run
cloudflared tunnel --config examples/push-demo/cloudflared.yml run push-demo &
mise run push-demo:serve
```
